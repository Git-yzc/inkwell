### REQ-01：工具栏只由双击中间呼出

**用户原话**：

> 希望在阅读模式下，呼出工具栏的触发方式仅仅只有双击屏幕中间时才可生效，
> 现在的阅读器我随便点击右边进行滑动的时候就会把工具栏呼出来，比较影响我使用。

**现状根因**：

- [Reader.tsx](../src/routes/Reader.tsx) 在 `window` 上同时监听 `pointerdown` 与
  `pointermove`，任何一次按下都会 `bump()` → `setBarVisible(true)`。
- 左右 18% 的翻页点按区在**外层文档**（盖在书籍 iframe 之上），所以点右侧翻页、
  或滑动起手按在右侧时，`pointerdown` 会冒泡到 `window`，工具栏就被叫出来了。
- 工具栏隐藏时还有一层「屏蔽层」，按下也会 `bump()`，等于又一条「点哪都能呼出」的路径。

**实现**：

1. `pointerdown` / `pointermove` 的处理改为 `bumpFromPointer`：
   **Android 上** `pointerType === 'touch'` 直接返回；鼠标 / 触控笔、以及 Windows 触摸屏
   保留旧行为（Windows 没有双击入口，不能把它的触摸呼出一并砍掉）。
2. Android 上不再渲染隐藏态屏蔽层（`!isAndroid()`）。屏蔽层的存在意义就是
   「按下 → 显示工具栏」，与「只认双击」冲突；隐藏态下顶栏 / 底栏本来就是
   `pointer-events: none`，点按不会误触里面的控件。
3. 双击判定仍由引擎负责：监听挂在**书籍文档**上，左右点按区在外层文档拦截，
   所以「只在中间区域生效」天然成立。双击时若已划词则不响应，并清掉双击顺带选中的词。

### REQ-02：滑动翻页阈值

**用户原话**：

> 目前翻页是单击右侧可以直接翻页，但是当我滑动翻页的时候，他会出现如图 1 这种，
> 翻页翻到这个程度还没有自动滑到下一页的情况，我觉得这个翻页触发条件设置的有些太苛刻了，
> 需要让他比较容易的就能翻页。

**现状根因**（读内核源码确认，不是猜测）：

- `packages/foliate-js/paginator.js` 的 `snap(vx)` 只把**松手瞬间的速度**代入
  `page = floor((start + end) / 2 + vx * size)`，**完全不看拖动距离**。
- 慢慢拖过 20% 再停住时，`vx ≈ 0`，中点仍在当前页 → 原地弹回。
  用户截图里「拖出下一栏一小截」正是这个状态。

**实现**（只在 `engine/index.ts`，不改 submodule）：

- 在已有的下拉手势 capture 监听里记录起点与起始页。
- `touchend` 时，若横向位移 ≥ **视口宽度的 18%（且不小于 36px）**、横向明显大于竖向、
  且内核当前页还停在起始页，就 `stopPropagation + preventDefault` 拦掉内核的
  `snap()`，直接调 `next()` / `prev()`。
- 若拖过了半页（内核的 `page` 已经变化），交给内核自己 snap，避免再 `next()` 跳两页。
- RTL 书按 `book.dir` 反转方向；多指、划词中、已判定为下拉书签的手势都不参与。
- ⚠️ **必须用 `touch.screenX` 而不是 `clientX` 量距离**：横向拖动时内核会
  `scrollBy(dx)` 把正文跟着手指一起滚，书籍 iframe 里的 `clientX` 因此几乎不变
  （实测拖 220px，`clientX` 只差 21px）。用 screen 坐标才能真正量出手指走了多远。
  这条是实测踩出来的，改手势时别改回 client。

### REQ-03：桌面单栏宽屏

**用户原话**：

> 桌面版需要加上宽屏阅读的模式可选，目前只有单栏和双栏的模式，
> 我希望在单栏的时候再加个宽屏模式可选，让文本可以自动填充到两边，
> 当然靠近边缘的冗余需要注意一下。

**现状根因**：

- 内核 `paginator.js` 的 `--_max-inline-size` 默认是 **720px**，
  且正文网格宽度 = `max-inline-size × max-column-count`。
  所以单栏在 2K/4K 屏上只占中间 720px，两侧大片空白 —— 这不是「页边距」设置造成的。

**实现**：

- `RendererSettings` 新增 `wideScreen: boolean`（默认 `false`，旧 localStorage 自动补默认值）。
- 引擎在单栏时把 `max-inline-size` 设为 `100000px`（等同「不设上限」）；
  双栏仍用内核默认的 720px，避免两栏宽到读不下去。
- 正文铺满后仍在左右各留约 7% 的空白（1100px 窗口实测每侧约 77px），
  即「靠近边缘的冗余」；上下留白仍由现有「页边距」控制。
- 设置面板在「单栏」下显示「单栏宽度：标准 / 宽屏」；切到双栏时该项隐藏但保留选择。

## 二、决策记录

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | **Android** 触摸完全不参与「叫出工具栏」；桌面鼠标与 Windows 触摸屏保留旧行为 | 需求只约束移动版；Windows 没有双击入口，砍掉会让触摸屏用户失去工具栏 |
| D2 | 移动端不再使用隐藏态屏蔽层 | 屏蔽层的唯一作用是「点按呼出」，与 D1 冲突 |
| D3 | 滑动阈值取 18% 正文区宽度、最小 36px | 比内核「只看速度」宽松；又不会把轻点误判成翻页 |
| D4 | 拖过半页时仍交给内核 snap | 内核已按中点翻页，再补 `next()` 会一次跳两页 |
| D5 | 宽屏不做成「任意行宽」，只提供标准 / 宽屏两档 | 需求是「单栏加一个宽屏可选」，不引入新的连续滑杆 |
| D6 | 宽屏只对单栏生效 | 双栏再放宽会让每栏不可读；需求也明确说「在单栏的时候」 |

## 三、验收口径

| 用例 | 期望 |
| --- | --- |
| Android / 触摸：点右侧翻页区 | 翻页；工具栏**不出现** |
| Android / 触摸：从正文起手滑动 | 滑动过程与松手后都不出现工具栏 |
| Android / 触摸：双击正文中间 | 工具栏显示；再双击隐藏 |
| 双击时已有选区 | 不切换工具栏（沿用 Q3） |
| 慢慢横滑约 20% 屏宽后松手 | 翻到下一页 / 上一页，不再弹回 |
| 横滑不足 18%（或主要竖向） | 不翻页；下拉书签手势照旧 |
| 快速轻扫 | 仍由内核按速度翻页，不受影响 |
| 桌面单栏：标准 → 宽屏 | 正文从 720px 扩到铺满窗口，两侧仍各留约 7% 空白 |
| 桌面双栏 | 宽屏选项隐藏，且宽度不受 `wideScreen` 影响 |
| 重启应用 | 宽屏选择被记住（localStorage） |

## 四、实测记录（2026-11-22）

**环境**：`pnpm tauri build --no-bundle` 产物（`src-tauri/target/release/inkwell.exe`），
复制到工作区外启动；数据目录指向临时副本，未动真实书库。窗口 1100×760 CSS px，
书为《毛泽东传》，用 CDP 的 `Input.dispatchTouchEvent` 派发真实触摸，
`Emulation.setUserAgentOverride` 把 UA 改成 Android 以启用双击逻辑。

### 工具栏

| 用例 | 结果 |
| --- | --- |
| 隐藏态点右侧翻页区（x=90% 宽） | 页码 26 → 27；顶栏 opacity **0** |
| 隐藏态慢速横滑 20% | 页码 27 → 28；顶栏 opacity **0** |
| 隐藏态点顶部 / 底部空白区 | 页码不变；顶栏 opacity **0** |
| 双击正文中间 | opacity 0 → **1** |
| 再双击 | opacity 1 → **0** |

### 滑动翻页（松手前停 320ms、再走 1px，让内核 `vx≈0`）

| 拖动距离 | 阈值 | 结果 |
| --- | --- | --- |
| 10%（110px） | 198px | 页码不变 ✅ |
| 20%（220px） | 198px | 页码 +1 ✅ |
| 30%（330px） | 198px | 页码 +1 ✅ |
| 向右拖 20%（上一页） | 198px | 页码 −1 ✅ |

> 这一步同时验证了「距离兜底」确实生效：内核在 `vx≈0` 时只会弹回原页，
> 页码能前进只能是我们直接调了 `next()`。
