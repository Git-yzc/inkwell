### REQ-2026-10-05-01 安卓端双击正文中间区域呼出上下工具栏

| 项目 | 内容 |
| --- | --- |
| 主题 | M（移动端优化） |
| 优先级 | 高 |
| 状态 | 已澄清（2026-10-05 定案：双击 = 显示 / 隐藏切换；本次只做 Android） |
| 提出日期 | 2026-10-05 |

**背景与动机**

安卓端阅读时，顶栏（书库 / 书名 / 加书签 / 目录 / 批注 / 设置）与底栏（进度条 + 百分比）
只在「刚进入」和「指针活动」后短暂出现，4 秒后自动隐藏。
手机上正文占满屏幕、没有鼠标移动，工具栏一旦隐藏，用户**缺少可靠的方式把它叫回来**：
现有实现只在 window 上监听 `pointermove` / `pointerdown` / `keydown`，
而正文位于 foliate-js 的 iframe 内，中间区域的点按落在书籍文档内部、不会冒泡到外层。

用户诉求：**双击正文中间区域**即可呼出上下两侧工具栏。

**需求描述**（原文照录）

> 我希望在安卓端添加双击中间区域可以呼出工具栏，也就是上下两侧的工具栏的功能。

附图（用户提供，Android 真机截图，进度 18%）：红框标出的即「中间区域」——
左右两侧各 18% 的翻页点按区**之外**、纵向占满正文区的那一块。

**验收标准**（草案，待用户确认后定稿）

1. Android 真机上，工具栏隐藏时，双击正文中间区域内任意位置 → 顶栏与底栏出现。
2. 工具栏显示时，双击同一区域 → 工具栏隐藏（若确认为「切换」语义，见 §四 Q1）。
3. 双击左侧 / 右侧 18% 翻页区**不**触发工具栏，仍按原逻辑翻页。
4. 双击不误触发翻页，也不误触发「下拉加书签」手势。
5. 双击后 4 秒无操作，工具栏按现有逻辑自动隐藏。

**影响面**（初步勘察，实现会话需复核）

- **事件入口**：正文在 iframe 内，事件不冒泡到外层（与 [BACKLOG.md](./BACKLOG.md) §2.1 记录的
  wheel 事件同源）。需在引擎的 `load` 事件里往书籍文档挂双击判定，参照现有做法
  —— [engine/index.ts](src/features/reader/engine/index.ts) 的 `#bindPullDown()` 与 `#onWheel`，
  换章节时用「记录 doc 实例」去重。
- **接口**：需在 [engine/types.ts](src/features/reader/engine/types.ts) 增加一个回调类型
  （如 `onToggleBars(fn)`），由 [Reader.tsx](src/routes/Reader.tsx) 接到 `setBarVisible` 上。
- **工具栏显隐**：自动隐藏逻辑在 [Reader.tsx](src/routes/Reader.tsx) 第 293–313 行
  （`bump()` + 4 秒计时器）；顶栏 / 底栏的 opacity 与 `pointerEvents` 在第 474–549 / 634–659 行。
- **翻页区**：左右两个绝对定位点按按钮在 [Reader.tsx](src/routes/Reader.tsx) 第 594–609 行
  （宽 `18%`，`top-0 bottom-12`）。
- **平台风险**：Android WebView 上双击可能同时触发系统选词 / 系统菜单，需真机确认并按需抑制。

**相关**：REQ-2026-10-05-03 与本文是同一处交互（工具栏呼出方式），两条必须一起实现。

**待确认**：无。Q1–Q3 已于 2026-10-05 定案（见 §四）：双击 = **显示 / 隐藏切换**；**本次只做 Android**；划词中 / 批注栏打开时**不响应**双击。

### REQ-2026-10-05-02 阅读页右下角常驻显示页号与进度百分比

| 项目 | 内容 |
| --- | --- |
| 主题 | M（移动端优化；**Android 与 Windows 两端都做**） |
| 优先级 | 中 |
| 状态 | 已澄清（2026-10-05 定案：页号取「全书位置」口径；**两端都做**） |
| 提出日期 | 2026-10-05 |

**背景与动机**

底栏（进度条 + 百分比）和顶栏一样，无操作 4 秒后自动隐藏。工具栏隐藏后，
阅读时**看不到自己读到哪儿了**。用户希望在正文右下角常驻一个轻量的位置指示。

**需求描述**（原文照录）

> 我希望在图中所示的位置补充上页号和进度百分比的显示

附图（用户提供，Android 真机截图，进度 18%，**此时工具栏是隐藏状态**）：红框位于
正文区**右下角**（约占屏宽 81%–97%、屏高 93%–97%），说明该指示应当**常驻**，
不随上下工具栏一起隐藏。

**验收标准**（草案，待用户确认后定稿）

1. 阅读界面右下角常驻显示「页号 + 进度百分比」，浅色 / 羊皮纸 / 深色三种主题下均清晰可读。
2. 上下工具栏隐藏时该指示仍可见；工具栏显示时与底栏进度条不互相遮挡（处理方式见 §四 Q5）。
3. 翻页、跳章、拖动进度条之后，数值实时更新，不滞后。
4. 不挡左右两侧 18% 的翻页点按区（该指示必须设为不接收指针事件）。
5. **Android 与 Windows 两端都要有**且表现一致（2026-10-05 用户澄清：这一条两端一起做）。

**已定口径**（2026-10-05，用户指定）

页号取 **A：全书位置**（Kindle 式），即把内核已有的 `location.current` / `location.total`
透传到 UI；**不做**逐章页数统计，也不做全书估算页码。显示形如 `1234 / 5678`。

**影响面**（初步勘察，实现会话需复核）

- **百分比：现成**。`fraction` 已随 `relocate` 更新，底栏用 `formatPercent`
  （[util.ts:30](src/lib/util.ts#L30)）渲染，见 [Reader.tsx:644–658](src/routes/Reader.tsx#L644-L658)。
- **页号：目前没有**。[types.ts](src/features/reader/engine/types.ts) 的 `ReaderLocation`（第 9–21 行）
  不含任何页码字段。内核侧有两类可用数据，都**尚未透传**：
  1. **全书「位置」**（Kindle 式）：`location.current / location.total`。
     由 [progress.js:88–92](packages/foliate-js/progress.js#L88-L92) 按 `sizePerLoc` 折算，
     已声明在 [foliate-js.d.ts:69](src/features/reader/engine/foliate-js.d.ts#L69)，
     但 [engine/index.ts:124–134](src/features/reader/engine/index.ts#L124-L134) 的 `toLocation`
     没有取它 —— **透传即可**，成本最低。
  2. **本章页数**（第 N / M 页）：[paginator.js:963–968](packages/foliate-js/paginator.js#L963-L968)
     的 `detail.size = 1 / (本章页数 − 2)`，`detail.fraction` 是**章内**占比。
     反推可得本章页码，但 `size` 同样**未透传**，需一并补进 `FoliateLocation` 与 `toLocation`。
  3. **全书真实总页数**：需要逐章渲染统计，代价高，**不建议**。
- **布局**：放在正文区容器（[Reader.tsx:552](src/routes/Reader.tsx#L552) 的 `div.relative`）内
  绝对定位到右下角，并设为不接收指针事件，避免挡住翻页点按区。
- **Android 安全区**：insets 已在 [MainActivity.kt:25–33](src-tauri/gen/android/app/src/main/java/com/inkwell/reader/MainActivity.kt#L25-L33)
  消费完毕，WebView 区域本身已避开状态栏 / 导航栏，**不要**再叠 `env(safe-area-inset-*)`。
- **潜在遮挡**：目录栏与批注栏都是 `w-80` 的 `aside`
  （[TocPanel.tsx:61](src/features/reader/TocPanel.tsx#L61)、[AnnotationPanel.tsx:93](src/features/annotation/AnnotationPanel.tsx#L93)），
  批注栏打开时会盖住右下角，需确认该指示是否随即隐藏。

**待确认**：无。Q4–Q7 已于 2026-10-05 定案：页号 = **A 全书位置**；指示在底栏显示时**上移让位**；滚动模式下**也显示**（页号退化为「位置」）；**两端都做**（Windows 也列入验收）。

### REQ-2026-10-05-03 修正「点按上下工具栏区域呼出工具栏」导致的进度条误触

| 项目 | 内容 |
| --- | --- |
| 主题 | M（移动端优化；机制两端都在，但本次只做 Android） |
| 优先级 | 高（误触会**真的改变阅读位置**，属数据 + 体验双损失） |
| 状态 | 已澄清（2026-10-05 定案：采用方案 B；与 REQ-2026-10-05-01 一起实现） |
| 类型 | Bug + 交互调整 |
| 提出日期 | 2026-10-05 |

**现象**（用户原文）

> 现在有个 bug，就是目前还没有实现双击中间区域呼出工具栏的功能，而是点击上下工具栏的位置呼出工具栏。
> 但是这样就带来了一个问题，当我点击上面或者下面的工具栏的时候，如果点击的位置不对，比如我点击的下面的进度条，
> 那么点击的时候他就会呼出工具栏的同时，将进度条也直接拉到我点击的位置，导致误触。
> 因此我希望你能像个办法规避掉这个误触的方法。或者如果没有什么好方法的话，
> 那就直接把点击上下呼出工具栏的功能直接删掉，全部改成双击中间区域来呼出或者关闭工具栏。

附图（用户提供，Android 真机截图）：红框标出底栏（进度条 + 18%）。

**根因分析**（读代码得出，实现会话请复核）

1. 工具栏显隐**不区分触发位置**：[Reader.tsx:293–313](src/routes/Reader.tsx#L293-L313) 在 `window` 上监听 `pointerdown`，
   任何一次按下都 `setBarVisible(true)` 并重置 4 秒计时器 —— 这就是「点按上下工具栏的位置也能呼出工具栏」的来源。
2. 隐藏态下顶栏 / 底栏是「透明 + 不接收指针事件」（[Reader.tsx:475–483](src/routes/Reader.tsx#L475-L483)、[Reader.tsx:635–642](src/routes/Reader.tsx#L635-L642)），
   但**那块屏幕位置仍然存在**；按下的目标会落到外层 `div` 上，事件继续冒泡到 `window` → 触发第 1 条 → 工具栏显示。
3. 工具栏在**同一个手势内**立刻变成可交互：React 对 `pointerdown` 这类离散事件是同步刷新的，
   所以紧随其后的兼容鼠标事件（`mousedown` / `click`）已经落在**刚显示出来的进度条**上；
   `input[type=range]` 在轨道上按下即按坐标设值 → 进度条被拉到点击位置，
   并且 [Reader.tsx:644–655](src/routes/Reader.tsx#L644-L655) 的 `onChange` 会调 `goToFraction()`，**真的跳走阅读位置**。
4. 同一机制也会命中**顶栏按钮**（点在「目录」的位置 → 呼出工具栏的同时把目录面板也打开）。
   用户只提到进度条，但根因相同，修的时候要一起堵住。

**需求**

给出一种规避误触的办法；若没有干净方案，则**彻底移除「点按上下工具栏区域呼出工具栏」**，
只保留「双击中间区域呼出 / 关闭工具栏」（即 REQ-2026-10-05-01 的功能）。

**候选方案**（供选择，实现时按选定方案落地）

| 方案 | 做法 | 优点 | 代价 / 风险 |
| --- | --- | --- | --- |
| **A. 只保留双击** | 去掉 `window` 上的 `pointerdown` 显示逻辑（仅保留 `pointermove` / 按键），工具栏只能靠双击中间区域切换 | 行为最一致、代码最简；一次手势不可能既呼出又命中控件 | 依赖 REQ-01 先落地；隐藏态那条带彻底不可点（本来也看不见） |
| **B. 隐藏态加屏蔽层**（推荐） | 工具栏隐藏时，在顶栏 / 底栏之上盖一层透明拦截层（可接收指针事件）；首次按下由它 `preventDefault()` + `stopPropagation()` 接管，只负责显示工具栏，整个手势被吞掉；工具栏显示后该层立即移除，下一次点按才落到真实控件 | 保留「点一下就唤出」的习惯，同时从根本上切断「同一手势二次命中」 | 多一层 DOM；`preventDefault()` 对触摸事件的影响需真机确认 |
| **C. 显示后短暂锁定** | 工具栏显示后 N 毫秒内让栏内控件不接收指针事件，之后解锁 | 改动最小 | 「想立刻拖进度条」会被吃掉，手感顿；阈值难调 |

**已定方案**（2026-10-05，按默认建议）

采用 **方案 B：隐藏态加屏蔽层**。工具栏隐藏时在顶栏 / 底栏之上盖一层透明拦截层，
首次按下由它 `preventDefault()` + `stopPropagation()` 整体吞掉、只负责显示工具栏；
工具栏显示后该层立即移除，下一次点按才落到真实控件。**保留**单点呼出的习惯。

> 实现提醒：屏蔽层必须能拿到 `pointerdown` 并阻断向 `window` 的冒泡，
> 否则 [Reader.tsx:293–313](src/routes/Reader.tsx#L293-L313) 的 `bump()` 仍会照常触发；
> 桌面端鼠标本就是「移动即显示」，屏蔽层不要影响它。

**验收标准**（草案）

1. 工具栏隐藏时，点按底栏所在的屏幕区域 → 进度条**不跳转**（`fraction` 值不变），也不触发任何按钮。
2. 工具栏隐藏时，点按顶栏所在的屏幕区域 → 不会顺手打开目录 / 批注 / 设置面板。
3. （方案 A / B）双击正文中间区域能正常呼出工具栏。
4. 工具栏**已经显示**时，点按进度条任意位置 → 仍能正常拖拽 / 跳转（不能为了防误触把正常操作也废掉）。
5. 桌面端鼠标操作不受影响。

**影响面**

- [Reader.tsx:293–313](src/routes/Reader.tsx#L293-L313)：`window` 级 `pointerdown` → `bump()`；方案 A 需要改写这里。
- [Reader.tsx:475–483](src/routes/Reader.tsx#L475-L483)、[Reader.tsx:635–642](src/routes/Reader.tsx#L635-L642)：顶栏 / 底栏隐藏态的 `opacity` 与 `pointerEvents`。
- [Reader.tsx:644–655](src/routes/Reader.tsx#L644-L655)：进度条 `input[type=range]` 的 `onChange` → `goToFraction`，误触的实际后果在这里。
- 与 REQ-2026-10-05-01 共用「双击中间区域」的引擎侧实现（`engine/index.ts` 往书籍文档挂监听），两条必须一起改。

**待确认**：无。Q8 已于 2026-10-05 定案：**方案 B（隐藏态加屏蔽层）**。

### REQ-2026-10-05-04 PDF 导入与阅读

### REQ-2026-10-05-06 修复页边距设置失效（非 0 即布局塌陷）

| 项目 | 内容 |
| --- | --- |
| 主题 | U（通用 / 双端 UI） |
| 优先级 | 高（每次阅读都在发生；**默认值 40 本身就处在坏状态**） |
| 状态 | 记录中（根因已定位到具体代码，修复方案已给） |
| 类型 | Bug |
| 提出日期 | 2026-10-05 |

**现象**（原文照录）

> 页边距我发现有些问题，0是正常情况，但是只要一不是0，就立马缩到了跟高的程度，
> 这个应该是设置有问题，你需要检查一下并将修复方案记录在案。

附图（用户提供，Windows 桌面版）：页边距 0 时正文铺满整页（正常）；页边距为 112 时正文被挤成中间一小块，上下留白巨大。

**根因（已定位到具体代码）**

1. 引擎把页边距**当裸数字**传给内核：[engine/index.ts:499](src/features/reader/engine/index.ts#L499) 的
   `renderer.setAttribute` 第二个参数是 `String(s.margin)` —— 传下去的是 `40` 这种**没有单位**的字符串。
2. 内核把这个字符串**原样塞进 CSS 变量**：[paginator.js:628–638](packages/foliate-js/paginator.js#L628-L638)，
   `margin` 分支走的是 `this.#top.style.setProperty`，变量名是 `--_margin`。
3. 该变量被当作**长度**用在两处：[paginator.js:484–487](packages/foliate-js/paginator.js#L484-L487) 的
   `grid-template-rows: minmax(var(--_margin), 1fr) …`，以及 [paginator.js:527](packages/foliate-js/paginator.js#L527) 的 `height: var(--_margin)`。
4. 于是出现**正好对应用户观察**的不对称：
   - `margin = 0` → `minmax(0, 1fr)`：裸 0 在 CSS 里**是合法长度**，声明成立，布局正常；
   - `margin = 40`（默认值）或任何非 0 → `minmax(40, 1fr)`：裸数字**不是合法长度**，
     该声明在计算值阶段失效，整条 `grid-template-rows` 塌掉 → 正文被压成内容高度的一小块。

**修复方案**（推荐 A）

| 方案 | 做法 | 说明 |
| --- | --- | --- |
| **A（推荐）** | [engine/index.ts:499](src/features/reader/engine/index.ts#L499) 传值时补上单位，让裸数字变成带 `px` 的字符串 | **一行改动**。内核 `#beforeRender` 是 `parseFloat`（[paginator.js:693](packages/foliate-js/paginator.js#L693)），带 `px` 照样取到 112，不影响后续计算 |
| B | 改 submodule 的 paginator 做兜底 | 不推荐：动内核、升级会冲突，而且错的本来就是我们这边 |
| C | 弃用内核的 margin 属性，自己在 `buildCss` 里做内边距 | 不推荐：行宽与分栏由内核计算，绕开它会两头打架 |

> 顺带说明（**这是设计，不是 bug，别改错**）：正文最大宽度受内核默认 `--_max-inline-size: 720px` 限制
> （[paginator.js:469](packages/foliate-js/paginator.js#L469)），所以宽屏下正文不会铺满整屏。这是行宽上限，本次不动；
> 若日后想更宽，另立需求。

**验收标准**（草案）

1. 页边距设 0 / 4 / 40 / 120 四档，正文都正常铺排：既不被压扁，也不出现异常留白。
2. 0 与 4 之间是**平滑变化**，不再有断崖。
3. 留白随数值单调变化（值越大，正文区域越小）。
4. 翻页 / 分栏 / 滚动模式均不回归。

**待确认**：见 §四 Q13。

- 全 App **没有** App 级主题概念：[globals.css](src/styles/globals.css) 只有字体变量，

- 「阅读主题」（浅色 / 羊皮纸 / 深色）其实**只作用于正文页面**，与 App 外壳配色是两回事，

**设计模型（建议）**

两个独立维度，别混：

| 维度 | 取值 | 作用范围 | 存放 |
| --- | --- | --- | --- |
| **App 主题（新）** | `light` / `dark` / `system`（**默认 `light`**） | 书库页、设置 / 目录 / 批注面板、阅读页顶栏与底栏、各类按钮与输入框 | 新增 App 级 store，localStorage 持久化（照 [reader-settings.ts](src/store/reader-settings.ts) 的写法） |
| 阅读主题（现有） | `light` / `sepia` / `dark` | **只作用于正文页面** | 现有 `reader-settings` store |

联动规则（Q15 定案）：切换 App 主题时**总是**把阅读主题设为该模式的默认值（夜间 → `dark`，白天 → `light`）。
选「跟随系统」时，**由系统深浅变化触发的那次切换走同一套规则**（系统转深色 → 阅读深色）。

**实现要点**

- Tailwind v4 的 `dark:` 变体默认**跟随系统**；要按 class / 属性切换，需在 [globals.css](src/styles/globals.css) 自定义 variant，例如
  `@custom-variant dark (&:where([data-app-theme=dark], [data-app-theme=dark] *));`，再在根节点挂 `data-app-theme`。
  这是本需求最容易踩坑的一步（不写这行，`dark:` 会一直听系统的）。
- **跟随系统**的实现：用 `window.matchMedia` 查询 `(prefers-color-scheme: dark)` 取初值，并监听其 `change` 事件实时跟随。
  Windows（WebView2）与 Android（系统 WebView）都上报系统主题，但 **Android 真机必须实测**「系统切深色 → App 是否即时跟随」。
- ⚠️ 挂到 DOM 上的 `data-app-theme` 必须是**解析后的实际主题**（`light` / `dark`），**不能**直接写 `system` ——
  否则自定义的 `dark:` 变体在跟随系统模式下永远匹配不上，表现为「选了跟随系统但一直不换色」。
- 更彻底的做法是把面板配色收敛成几个 CSS 变量（`--app-bg` / `--app-surface` / `--app-fg` / `--app-muted` / `--app-border`），
  组件改用变量；但 64 处替换要一次做完，按最小改动优先。
- 阅读页顶栏 / 底栏现在用的是**阅读主题**颜色（[Reader.tsx:475–483](src/routes/Reader.tsx#L475-L483)、[Reader.tsx:635–642](src/routes/Reader.tsx#L635-L642)），
  **已定**（Q17 选 A）：改为**跟 App 主题**，正文配色仍由阅读主题控制。

**验收标准**（草案）

### 8.3 实现期间对设计的两处补充（原文档未写明）

1. **双击的判定方式**：Android WebView 关掉缩放后不保证派发 `dblclick`，所以自己按
   `pointerup` 判定。副作用是**牺牲了「双击选词」** —— 第二次点按若带出选区会被我们清掉
   （否则「工具栏 + 批注栏」会一起弹）。长按选词不受影响。这是让「双击呼出工具栏」
   在一整屏文字上也能用的必要取舍。
2. **PDF 强制单页**：内核原先把不带 `spread` 的固定版式按跨页排（桌面宽屏下左右各一页），
   会让页码与进度跳着走（1、3、5…）。我们在 Vite transform 里补 `spread:'none'`，
   一页一屏。submodule 未改动。
