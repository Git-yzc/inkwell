## 三、决策定案（2026-10-11，用户逐条确认）

### A. 双页展示 —— ❌ 取消

| 原问题 | 定案 |
| --- | --- |
| Q1 「双页」与现有「分栏」的关系 | **就是分栏的意思**。用户查看后确认现有「单栏 / 双栏」已满足，**不再单独开发** |
| Q2 是否自动退回单页 | 作废（沿用现有分栏行为） |
| Q3 是否首页单独一页 | 作废 |
| Q4 PDF / 漫画是否套双页 | 作废 |
| Q5 双页下翻页单位 | 作废 |

> 结论：**本期只有一条新功能 —— 翻页动效。** 分栏维持现状，不改设置项、不改内核参数。

### B. 翻页动效 —— ✅ 定案

| # | 问题 | 定案 |
| --- | --- | --- |
| **Q6** | 动效形态 | **真·翻纸**。**下一页**：从**右下方**卷起一页、向**左**翻过去。**上一页**同样有动效，**方向与下一页相反**（左下角卷起、向右翻回）。方向**不随书籍书写方向镜像**（RTL / 竖排书也同向） |
| **Q7** | 适用范围 | **只在「翻页」模式**；**滚动模式不做**。目录跳转、进度条跳转**保持原样**（无动效、直接到位）。动效只发生在「当前页 → 下一页 / 上一页」这种**相邻翻页**上 |
| **Q8** | 时长 / 缓动 / 可关闭 | 参考业内成熟实现。业内常见量级：Apple Books 翻页约 0.5s、turn.js 默认 600ms、Material 复杂转场 300–500ms。**暂定 500ms + easeInOutCubic**（≈ `cubic-bezier(0.65, 0, 0.35, 1)`），实现时以实机手感微调。**必须能关闭**；设置面板给「翻页动效」选项，至少含**关 / 滑动 / 翻纸**三档（「滑动」即内核自带那套 300ms 横向滑动） |
| **Q9** | 掉帧兜底 | **频繁掉帧时弹应用内提示**，建议手动改到「滑动」：<br>• **每次切到「翻纸」只提醒一次**；<br>• 之后再掉帧**不再提醒**；<br>• 只有把翻纸**关掉再重新打开**才重置标记，从而**可以再提醒一次** |
| **Q10** | 并发翻页 | **加锁**：动效播放期间拒绝新的翻页输入（左右点按、滚轮、方向键、手势），动效结束或超时后解锁 |

> ⚠️ Q8 的时长/缓动与 Q9 的「频繁掉帧」判据都是**建议初值**，实现时按实机微调；
> 本次查外部资料时 Web 搜索端点是坏的（HTTP 401），上面的业内量级来自通用经验，**实现前应再核对**。

**细节定案（2026-10-11，用户补充）**

| # | 细节 | 定案 |
| --- | --- | --- |
| D1 | **上一页**是否播放动效 | ✅ **要**，方向与下一页**相反** |
| D2 | **RTL / 竖排书籍**方向 | ✅ **不镜像** —— 一律「右下卷起向左」为下一页，与书籍书写方向无关 |
| D3 | 动效**默认档位** | ✅ **默认「关」**（不打扰，用户自己去设置里开） |
| D4 | 「已提醒」标记是否跨 App 重启 | ✅ **重启后不重置** —— 标记要持久化（localStorage）；只有翻纸**关→开**才重置 |
| D5 | **PDF / 漫画**是否也给翻纸 | ✅ **先不做** —— PDF / 漫画不套翻纸动效，维持现状 |
| D6 | **输入方式 / Windows 手势** | ✅ **触摸屏与触控板都做手势**（Windows 也做），可以有**交互过程**；**鼠标**操作时**自动播放**对应动效，不跟手 |

## 四、期望行为（按定案收敛）

1. **翻页动效**：Windows 与 Android 的「翻页」模式下，相邻翻页（上一页 / 下一页）播放仿纸质书翻卷动效。
   输入方式分两路（D6）：**触摸屏 / 触控板**走手势，可以有**交互过程**（跟着手指/手势走）；
   **鼠标**（点按翻页区、滚轮、方向键）**自动播放**动效，不跟手。
2. **翻纸方向**：**下一页**从右下角卷起、向左翻；**上一页**方向相反（左下角卷起向右）。
   方向**不随书籍书写方向镜像**（RTL / 竖排书也一样）。
3. **只在翻页模式**：滚动模式、目录跳转、进度条跳转**都不播放**动效。
4. **默认关 + 可切换**：设置面板可选 关 / 滑动 / 翻纸，**默认「关」**；关闭后与现在完全一致。
5. **掉帧只提醒一次**：切到「翻纸」后，若频繁掉帧，弹一次中文提示建议改「滑动」；
   用户不理会就不再打扰；翻纸**关→开**后才可能再提醒一次。
   **重启 App 不重置**该标记（持久化），否则重启后又会来打扰一次。
6. **加锁**：动效期间不响应并发翻页输入，不会跳页 / 错页 / 双重翻页。
7. **不得破坏**现有能力：CFI 续读、进度百分比与进度条、角标、批注（高亮 / 笔记 / 书签）、
   左右点按 / 滚轮 / 方向键 / 双击呼出工具栏 / 下拉加书签、页边距与中文排版、分栏。
8. 固定版式（PDF / 漫画）：**不套翻纸动效**（D5 已定案「先不做」），维持现状。

## 五、实现路径（已定案，待开工）

> 骨架（待实现时细化）：这是**自定义动效层**，内核只能帮到「滑动」那一步。

1. **设置项**：[`RendererSettings`](../src/features/reader/engine/types.ts) 新增
   `pageTurn: 'none' | 'slide' | 'curl'`（命名待定），加在
   [`SettingsPanel.tsx`](../src/features/reader/SettingsPanel.tsx)；旧数据用默认值兜底
   （[`reader-settings.ts`](../src/store/reader-settings.ts) 已有 `{...DEFAULT_SETTINGS, ...parsed}`）。
2. **动效层放在引擎里**：只允许在
   [`src/features/reader/engine/`](../src/features/reader/engine/) 接触内核（AGENTS.md 铁律 3）。
   `next()` / `prev()`（[`engine/index.ts:537-543`](../src/features/reader/engine/index.ts)）
   是唯一入口 —— 动效与加锁都收在这里。
3. **「拿什么当纸面」**：正文在 iframe 里，最可行的路线是**对当前页做位图快照**，
   叠到 paginator 视图容器上做 CSS 3D 变换 + 卷页阴影，动画结束后再真正执行内核翻页并移除快照。
   **必须先做 spike**（DPR / 主题底色 / 字体抗锯齿 / 快照时机 / Android WebView 性能），
   再决定最终方案。
4. **加锁**：动效期间置锁，拒绝新的翻页调用；与内核自身的 `#locked` 语义保持一致，
   超时兜底解锁（避免动效异常导致永久锁死）。
5. **掉帧检测**：在动效播放期间用 `requestAnimationFrame` 记帧时长，
   按定案的门槛与「只提醒一次」策略弹提示。判据常量与阈值**实现时定**。
6. ⚠️ 别把动效逻辑散到 React 组件里；React 侧只负责设置项与那条提示。

## 六、验收标准（实现后按此验）

1. **翻纸方向**：翻页模式下点「下一页」，可见页面从右下角卷起向左翻；「上一页」为镜像。
2. **范围正确**：滚动模式、目录跳转、进度条跳转**没有**翻纸动效。
3. **可关闭**：设置改成「关」后翻页与现在完全一致；改「滑动」是横向滑动。
4. **加锁有效**：动效期间连点 / 连滚 / 按住方向键，不会连翻多页或错页。
5. **掉帧提醒**：人为制造频繁掉帧时弹一次提示；继续掉帧不再弹；
   翻纸**关→开**后再掉帧能再弹一次。
6. **回归**：CFI 续读、进度条、角标、批注高亮位置、点按 / 滚轮 / 方向键 /
   下拉加书签、分栏全部照旧（高亮不偏移用 [BACKLOG §3.4](BACKLOG.md) 的
   `overlayer.hitTest()` 验证）。
7. `pnpm typecheck` / `pnpm lint` 干净；按 [AGENTS.md](../AGENTS.md) §5.4 用 CDP 驱动
   **真实应用**验证；Android **必须真机验证**帧率（本机没设备就如实标注「未验」）。
