## 一、需求原文（转述）

> 然后书签的图案，包括交互动效需要优化一下。在安卓端，我希望做成参考图这种：
> 下拉的时候整个页面跟着下拉、提示记录书签，松手放开后书签图案就显示在页面上；
> 再次下拉就是删除书签，图案消失。而在 Windows 端就不用这么麻烦，直接在对应的页上
> 显示对应的书签图案即可，删除的时候把图案去掉即可。另外注意，双栏和单栏的书签显示
> 互不相通，单栏显示单栏的、双栏显示双栏的，图案位置都在右上角。
>
> （追加）书签和批注要分开，两个单独记录 —— 书签是书签，批注是批注。

**参考图**（用户提供的截图，非本应用现状）：

1. 深色阅读页**右上角**有一条**蓝色缎带**（书签图案）；
2. 页面顶部被整体下拉、上方露出灰色区域，中间是「**↑ 松手添加书签**」提示。

拆成四条：

- **REQ-2026-10-11-04 页上书签图案**：在**当前页右上角**显示书签图案。
- **REQ-2026-10-11-05 下拉手势动效**：下拉时**整页跟在手指下**并提示，松手添加 → 图案出现；
  再次下拉 = 删除 → 图案消失。
- **REQ-2026-10-11-06 单栏 / 双栏书签互不相通**：单栏只显示单栏的书签，双栏只显示双栏的书签；
  两侧图案都在右上角。
- **REQ-2026-10-11-07 书签与批注分开**：侧栏里「书签」「批注」两个单独列表，各自计数与操作。

| **B2** | 双栏时图案贴哪 | ✅ **整屏右上角** —— 双栏时就是**右栏的右上角**，两者是同一处 |

## 四、书签与批注分开（REQ-2026-10-11-07）

**现状**：侧栏只有一个「批注」面板（[`AnnotationPanel.tsx`](../src/features/annotation/AnnotationPanel.tsx)），
书签混在里面（[第 15-28 行](../src/features/annotation/AnnotationPanel.tsx)、
[第 89-101 行](../src/features/annotation/AnnotationPanel.tsx) 的计数、[第 114-119 行](../src/features/annotation/AnnotationPanel.tsx) 的空状态），
顶栏入口也只写「批注 N」（[Reader.tsx:650-660](../src/routes/Reader.tsx)）。

**期望**：

1. 侧栏拆成**两个单独列表**：**「书签」**与**「批注」**（两个分区或两个页签）。
2. 各自的计数、空状态、删除、跳转都独立；书签列表里点一条 → 跳到该书签。
3. 顶栏入口：**保留单一的「批注」入口**（手机顶栏已很挤，不再加第二个按钮），
   面板内用两个页签切换；顶栏「批注」的计数**只数批注**（书签不计入）。

**B13 定案（2026-10-11）**：**不拆表**。现状 `annotations` 已用 `type` 区分两类，
只做 **UI 分区 + 查询过滤**，不额外加数据迁移。

## 五、期望行为（按定案收敛）

1. **图案**：有书签的页**右上角**显示缎带图案（Windows 直接显示；Android 下拉添加后显示）。
2. **下拉（Android + Windows 触控 / 触控板）**：整页正文跟手下拉、顶部按参考图提示；
   松手过线添加书签、图案出现；已有书签时下拉 = 删除、图案消失；未过线回弹且不改数据。
3. **Windows 鼠标**：不做跟手，翻页 / 加书签时**自动播放**对应动效。
4. **配色**：红 / 蓝 / 绿 / 琥珀四色可选，且不与三种阅读主题底色冲突。
5. **互不相通（数据层）**：单栏加的书签切到双栏**不显示**，反之亦然；历史书签归单栏。
6. **侧栏分开**：书签、批注两个独立列表；跳转走书签列表，图案本身不可点。
7. **滚动模式**：不显示图案、不响应手势。
8. **不得破坏**：顶栏 ☆ 增删书签、批注高亮、进度、分栏、翻页动效（见另一份需求）等全部照旧。

## 六、实现路径（决策定案后）

1. **数据库迁移 v2**：`annotations` 加一列（如 `layout TEXT NOT NULL DEFAULT 'single'`），
   在 [db.rs](../src-tauri/src/db.rs) 的 `MIGRATIONS` **末尾追加**（已发布迁移不可改）；
   历史行自动落成单栏，正好符合 B1。同步 [annotation.rs](../src-tauri/src/annotation.rs) /
   [lib.rs](../src-tauri/src/lib.rs) / [api.ts](../src/lib/api.ts)。
2. **图案层**：正文容器上加一层**右上角**缎带（绝对定位、不接收指针事件），
   按「当前页是否有本书签 + `layout` 与当前布局一致」决定显隐。
3. **下拉跟手**：把下拉回调从三态扩成**连续位移量**（`number \| null`），
   React 侧对**正文容器**做 `transform: translateY(...)` + 阻尼，松手回弹；
   阈值沿用现有 36 / 96 / 1.6 再按观感调。
4. **Windows 输入区分**：触控 / 触控板走跟手；鼠标走自动播放（入口是现有的翻页点按与顶栏 ☆）。
5. **侧栏拆分**：新增「书签」「批注」两个列表（复用现有 `AnnotationPanel` 的行样式），
   各自过滤 `type`。
6. ⚠️ 手势与动效逻辑收在 [src/features/reader/engine/](../src/features/reader/engine/)（AGENTS.md 铁律 3）。

**已知限制（需要你决定）**：

- **Windows 触控板的双指下拉做不到**：WebView2 里触控板与鼠标滚轮**都只给 `wheel` 事件**，
  拿不到来源信息，无法与滚轮翻页区分。**触摸屏与 Android 的触摸都可用**（走 `touch` 事件，已实测）。
  B11 的「触控板」这一半需要一个别的触发方式（例如：触控板在正文顶端继续下拉算作书签手势），
  等你定；翻页动效那边的触控板横向滑动不受此限。
- **Android 真机未验**（本机没有设备）：手势与缎带只在本机用 CDP 派发触摸事件验证过。

**真机反馈后的微调（2026-10-11，用户装了 0.3.0 预览包）**：

- **缎带不要贴在最右边**：原来 `right: 0` 直接贴在窗口右缘，看着像贴在窗口上而不是书本上。
  改为 **`right: 14px`**（常量 `RIBBON_INSET_PX`，在 `Reader.tsx` 顶部，
  以后要调手感只改这一个数）。CDP 复测：缎带右缘距窗口右缘 **14px**。

**真机反馈后的返工（第二轮，2026-10-11）**：用户装上 0.3.0 后在**安卓真机**上发现两个问题，都已修。

**① 缎带压在正文上**：缎带固定 34px 高、贴在正文区顶部，而页面的**上边距**取决于「页边距」设置 ——
页边距小的时候缎带就伸进正文里了（桌面实测：页边距 40 时缎带底距正文顶只剩 13px，手机上更小）。
现在缎带高度按页边距缩放：`max(12, min(26, margin - 10))`（`ribbonHeight` 常量），

**② 下拉时整页乱晃、还翻到下一页**：根因是**内核在同一个书籍文档上也挂了 touch 处理器**
（`paginator.js:571-575`），它把任何拖动都当横向滑动（`scrollBy(dx)`）、
松手再按横向速度 `snap()` —— 于是下拉和翻页在抢同一个手势。
修法：把我们挂的下拉监听改成 **capture 阶段**（比内核挂在同一个 Document 上的冒泡监听先执行），
一旦判定为竖直下拉就 `e.stopPropagation()`，这一轮手势内核完全收不到；
**松手时再拦一次**，免得它拿旧的 `vx` 去翻页。摘监听时第三个参数必须与注册一致（`true`）。

实测（CDP 派发真实触摸事件，`Input.dispatchTouchEvent`）：

| 用例 | 修前 | 修后 |
| --- | --- | --- |
| 竖直下拉 170px | 页面横向漂移、可能翻页 | `renderer.start` **不变**（5760→5760）、页码**不变**（8→8）、页面跟手下移 92.8px |
| 下拉松手 | 可能翻页 | 只切换书签，页码不动、回弹到 0 |
| 横向滑动翻页（回归） | 正常 | 正常（8→9，`start` +720） |

> 顺带调了手感：前 90px 与手指 1:1（真机上「直上直下」），之后带阻尼，最多 160px。
